# Портфолио

Одностраничное портфолио на React, Vite и TypeScript публикуется на GitHub Pages. Карточки ведут на уже опубликованные материалы DNS и ВсеИнструментов. Их исходники и процессы публикации остаются независимыми.

## Запуск

Node указан в `.nvmrc`; одинаковая версия используется локально и в Actions.

```sh
nvm use
npm ci
npm run dev
```

```sh
npm run check       # проверка типов и все автотесты
npm run build       # сборка в dist
npm run check:output # ссылки на локальные файлы собранной страницы и manifest
npm run preview -- --port 4173 --strictPort # просмотр готовой сборки
```

`npm run verify` последовательно выполняет проверки, сборку и проверку результата.

На текущем хосте [через Tailscale на порту `4173`](http://100.120.99.74:4173/) работает Vite dev-сервер. Он подхватывает правки в исходниках без сборки. Если сервер остановлен, запусти его командой:

```sh
PAGES_BASE_PATH=/ npm run dev -- --host 0.0.0.0 --port 4173 --strictPort
```

Для проверки готовой сборки на том же порту сначала останови dev-сервер, затем запусти `npm run preview`.

## Порядок работы

- До правки найди места, которые используют изменяемый код. Начни с кода проекта, затем проверь возможности платформы и установленные зависимости. Выбери самое простое решение, которое полностью закрывает задачу.
- До добавления движка, зависимости или переделки нескольких частей объясни, зачем это нужно. Если есть более простой вариант, назови его и укажи, где его перестанет хватать.
- Добавляй зависимости под конкретную задачу. Используй npm и обновляй `package-lock.json` вместе с `package.json`.

## Архитектурные решения

- Портфолио работает как одна страница. Добавление внутренних страниц требует отдельного решения о прямых адресах на Pages. Маршрутизатор, глобальное хранилище и UI-библиотеку добавляй только под задачу. Сейчас они отсутствуют.
- Проект содержит ссылки на презентацию, прототип, журнал и доступные деморежимы. Не все виды ссылок обязательны.
- Эффекты изолируются по контейнеру и жизненному циклу. Motion, GSAP и WebGL подключаются по задаче; сейчас они не установлены.
- Для отдельного журнала портфолио предусмотрен React + Fluid Functionalism. Сам журнал и его зависимости пока не реализованы. Предусмотри фильтры по периоду и проекту, состояния загрузки, ошибки и пустой выдачи. Большие журналы запрашивай постранично.
- Worker + D1 рассматривается как вариант инфраструктуры аналитики. Выбор зависит от проверки совместимости с существующей телеметрией по [правилам аналитики](src/analytics/AGENTS.md).
- На стартовой странице портфолио пока стоит `noindex`: политика индексации самого портфолио еще не определена. Существующие прототипы, журналы и презентации должны сохранить свой `noindex`.

## GitHub Pages

[Публичное портфолио](https://nikomb.github.io/main/) публикуется из [NiKomb/main](https://github.com/NiKomb/main).

1. Добавить этот локальный репозиторий в выбранный GitHub-репозиторий.
2. В Settings → Pages выбрать Source: GitHub Actions.
3. Push в `main` запускает проверки, сборку и публикацию. PR выполняет только проверки и сборку.

Workflow автоматически выбирает `/имя-репозитория/`; для репозитория `owner.github.io` — `/`. Для собственного домена задать repository variable `PAGES_BASE_PATH` равной `/`. Для другого пути можно указать `/нужный-путь/`.

Локальная проверка размещения в подпапке:

```sh
PAGES_BASE_PATH=/main/ npm run build
PAGES_BASE_PATH=/main/ npm run check:output
PAGES_BASE_PATH=/main/ npm run preview -- --port 4173 --strictPort
```

Открывать адрес с тем же префиксом. Импортируемые изображения обрабатывает Vite; файлы из public в компонентах адресовать через `import.meta.env.BASE_URL`.

Собранный dist не коммитится; Pages получает проверенный артефакт. Откат публикации — revert проблемного коммита и новый push.

## Приемка изменений

Локально выбирай проверки по области изменений. Воспроизведи сценарий, который может сломаться из-за правки. `npm run check` запускает все автотесты. Для точечной проверки запускай нужные файлы напрямую.

- Для документации проверь `git diff --check` и сверь изменённые команды с `package.json` или конфигурацией CI.
- Для текста и разметки интерфейса выполни `npm run build` и проверь изменённый участок в браузере по [правилам интерфейса](src/AGENTS.md). При изменении `index.html`, путей к ресурсам или настроек сборки дополнительно выполни `npm run check:output` с тем же `PAGES_BASE_PATH`, что и при сборке.
- Для логики выполни `npm exec -- tsc --noEmit` и запусти только тесты затронутой логики и связанных сценариев. Например, при изменении навигации по галерее запусти `node --test scripts/media-navigation.test.mjs`. Для новой логики добавь точечный тест, если существующие проверки пропустят регрессию. Используй профильные правила проверки [эффектов](src/effects/AGENTS.md) или [аналитики](src/analytics/AGENTS.md), если они применимы.

Полный `npm run verify` запускай локально по запросу или если правка затрагивает несколько областей и точечных проверок недостаточно. GitHub Actions выполняет полный прогон для pull request в `main` и перед публикацией.

Проверка внешних ссылок выполняется отдельно: временная недоступность другого сайта не блокирует сборку портфолио. Автопроверка сборки проверяет локальные ресурсы, а не доступность всех внешних проектов.

## Итоговый отчёт

- Сообщай, что проверено и что осталось непроверенным.
- Объясняй простыми словами, что запускает действие, по какому правилу код выбирает результат и что происходит дальше. Укажи условия и исключения, если они меняют результат. Сверяй детали с кодом и явно обозначай предположения и открытые решения.
- Для интерфейса назови действие, элемент и видимый результат. Например, «Нажми „К кейсам“ над оглавлением. Страница вернётся к списку кейсов».
- Укажи статус коммита и публикации. Если внесены только локальные правки, пиши «Локальная правка, без коммита и публикации».
- Если остались незакоммиченные изменения, пиши «Есть незакоммиченные правки».
